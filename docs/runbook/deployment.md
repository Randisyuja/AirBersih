# Runbook: Prosedur Deployment & Rilis

Panduan langkah-demi-langkah penerapan aplikasi ke lingkungan *Staging* dan *Production* (Docker Cloud / Railway / VPS).

---

## 📋 Checklist Pra-Rilis (Pre-Flight Checklist)

Sebelum melakukan deployment ke lingkungan produksi, pastikan:
- [ ] Semua unit test lolos secara lokal (`python manage.py test`).
- [ ] `DEBUG` diset ke `False` pada variabel lingkungan produksi.
- [ ] `SECRET_KEY` unik dan tidak menggunakan default lokal.
- [ ] `ALLOWED_HOSTS` dan `CSRF_TRUSTED_ORIGINS` mencakup domain resmi produksi (contoh: `airbersih.domain.com` atau `.railway.app`).
- [ ] File migrasi database telah dikomit ke Git branch rilis (`main`).

---

## 🚀 Prosedur Deployment

### Metode 1: Platform-as-a-Service (Railway / Render)
Aplikasi telah dilengkapi [Procfile](file:///d:/Randi/water_pay/Procfile):
```text
web: python manage.py collectstatic --noinput && gunicorn airBersih.wsgi:application
```
1. Hubungkan repositori GitHub ke project Railway.
2. Tambahkan variabel lingkungan pada tab **Variables**:
   - `SECRET_KEY` = `<strong_random_secret>`
   - `DEBUG` = `False`
   - `DATABASE_URL` = `<auto-generated_postgres_url>`
   - `ALLOWED_HOSTS` = `.railway.app,domainku.com`
   - `CSRF_TRUSTED_ORIGINS` = `https://*.railway.app,https://domainku.com`
3. Railway akan otomatis membangun image menggunakan [Dockerfile](file:///d:/Randi/water_pay/Dockerfile) atau Python buildpack dan mengeksekusi start command.

### Metode 2: Self-Hosted Docker Compose / VPS
1. Tarik perubahan kode terbaru pada server:
   ```bash
   git pull origin main
   ```
2. Jalankan build dan restart kontainer:
   ```bash
   docker compose -f docker-compose.yml up -d --build
   ```
3. Verifikasi log container untuk memastikan migrasi berhasil:
   ```bash
   docker compose logs -f web --tail=50
   ```

## 🔒 Konfigurasi Keamanan Produksi

Pada [airBersih/settings.py](file:///d:/Randi/water_pay/airBersih/settings.py), pengaturan keamanan produksi berikut aktif:
- `SESSION_COOKIE_SECURE = True`: Mencegah cookie session dikirim melalui sambungan HTTP tidak terenkripsi.
- `CSRF_COOKIE_SECURE = True`: Mencegah CSRF token terbaca melalui plain text.
- `SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')`: Mendukung load balancer / reverse proxy HTTPS termination.
- `STATICFILES_STORAGE`: Menggunakan WhiteNoise Compressed Manifest untuk caching file statis jangka panjang secara otomatis.

## ⏪ Prosedur Rollback Cepat

Jika ditemukan bug kritis setelah rilis:
1. Kembalikan kode ke commit sebelumnya:
   ```bash
   git checkout <commit_hash_stabil>
   ```
2. Re-build dan start ulang kontainer:
   ```bash
   docker compose up -d --build
   ```
3. Jika migrasi database perlu di-rollback:
   ```bash
   docker compose exec web python manage.py migrate <nama_app> <nomor_migrasi_sebelumnya>
   ```
